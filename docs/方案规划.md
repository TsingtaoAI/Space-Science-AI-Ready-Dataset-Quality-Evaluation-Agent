# 方案规划 · 空间科学智能就绪数据集质量评价智能体

> 系统版本 0.8.0 ｜ 规则版本 0.8.0 ｜ 对应交付物 DEL-1 ｜ 依据：需求说明书、评分标准 v1.1（含附件一档位标签）、交付材料清单 v1.1

## 1. 技术路线

**核心判断**：空间科学数据没有内禀真值，判据只能来自数据之外——标签自身的声明与物理关系、来源事件目录的约定、同一基础数据的其他质量版本。
据此采用三层确定性判据，由强到弱：

1. **声明与物理一致性**（单数据集）：标签结构、文件配对、数值合法性；采样率 × 时长 = 点数、声明尺寸 = 图像尺寸、起止时刻 = 观测时刻；
   活动区中心位于日面内、目标框面积与像素数相符；事件类型与来源目录一致；事件身份标识与同批格式一致。
   CME 动能 ≈ ½·质量·速度² 等数值关系也会计算，但属附件一的非计分轨，只作为待复核提示。
   **同一事件跨样本一致**（借鉴发榜方参考代码）：LASCO C2 的三帧以同一图像时刻成组、相邻帧标注应与中心帧一致；AIA 同一 HEK 事件出现在约 9 张图像中，类别与时刻应一致——取多数值为参考，与之不同的样本判类别错标或时段抖动（C05 / B05，只在没有同源版本时运行）。
2. **同源质量版本对照**（多数据集）：同一基础数据的多个版本逐样本、逐标注元素比较，判出缺失、错标、漏标、虚标、偏移及其程度。
3. **统计离群**：只落「待判定」，不直接判缺陷。

**两条底线**：

- **结论可复算**：计量、判定、计分与排序全部由确定性程序按规格公式完成；默认不调用模型（模型服务消耗 0），同一输入重跑逐字节一致。
- **模型只做规则做不了的事**：`--use-llm` 时两个子代理分别「读说明文档、抽取可核对的声明」与「改写整改建议的表述」，都不下结论、不算分（第 3.1 节）。
- **只报能证实的**：附件一的「非计分轨」（需外部基准方可判定）一律弃报为「待判定」并写明需补充的基准材料；
  附件一污染项目之外的现象（如图像像素被改动）只列待复核，不判缺陷。

## 2. 数据范围

| 数据类型 | 数据集类型 | 公开集数据 | 样本数 | 标注元素 |
|---|---|---|---:|---|
| 图像 | 事件标注型（HEK 事件，外接多边形或单一时刻） | SDO/AIA、SDO/HMI 活动区；SOHO/LASCO C2 日冕物质抛射 | 3150 / 3017 / 10790（每版本） | 事件：类型、多边形、起止时刻、物理参数 |
| 图像 | 矩形框标注型 | DMSP SSUSI 极光 | 286 | 矩形框：类别 PCA / TPA / unclear |
| 图像 | 多边形分割型 | 气辉 EPB 等离子体泡 | 1350 | 多边形掩膜 |
| 时序 | 事件区间标注型 | 地磁 ULF 1 Hz 时序 | 6120 | 事件区间：Pi2 / Pc 类型 |

公开集 6 类 × 5 档（clean、P1～P4），共 30 个数据包、123,565 个样本；档位与污染项目见评分标准附件一。
已验证范围即上述四种数据集类型；其他类型通过规格扩展（第 5 节），未验证前不出具结论。

## 3. 智能体组成与构建方式

全部构件登记在 `agent/`（manifest / tools / skills / rules / memory / plugins），由 `tools/gen_agent_registry.py` 从规格与检查器注册表生成，测试保证与实现同步。

### 3.1 三类载体划分与依据

| 载体 | 数量 | 承载什么 | 划分依据 |
|---|---:|---|---|
| 工具 | 14 个检查器 + 4 个基础工具 | 对数据集执行确定性动作：47 项检查（45 项已实现）、数据加载、汇总评分、交付物输出 | 有执行体、有副作用的归工具；每个检查编号恰好归属一个工具 |
| 技能 | 16 项 | 判定知识：缺陷代码与计分轨、各标注族约定、物理关系与容差、版本对照判据、跨样本分组、文档声明比对口径、子代理提示词、汇总评分规则 | 只是知识、没有执行体；全部写在规格 YAML 中，规则版本即技能版本 |
| 规则 | 12 条 | 行为约束：何时转待判定、什么结论不得输出、失败如何重试、何时终止 | 约束「不许做什么 / 必须怎么做」，不承载判定知识 |

另有记忆 2 类（单次运行内，不跨运行持久化）、插件 3 个（检查器注册、标注族定义、模型客户端——默认关闭）、子代理 2 个（默认关闭）。

**子代理与划分依据**：只把规则做不了、且不影响结论可复算的两件事交给模型，其余全部是确定性程序。

| 子代理 | 职责 | 输入 / 输出契约 | 委派条件 | 矛盾仲裁 |
|---|---|---|---|---|
| doc_claim_extractor | 读说明文档，抽取样本数、类别、时段、尺寸、模态等可核对的声明 | 文档正文 → `{claims:[{field, value, quote}]}`，quote 为文档原文 | `--use-llm` 且数据集有说明文档（D04） | 同一文档调用 2 次只采用一致的声明；摘录在文档中找不到即丢弃；比对与判定由 D04 程序完成，模型不出结论 |
| remediation_writer | 把评分卡主要缺陷的整改建议改写得更具体 | 检查名称、缺陷类型、数量、示例与通用建议 → ≤ 80 字整改步骤 | `--use-llm`，全部结论确定之后 | 不参与判定与计分；失败则保留规格中的通用建议 |

**拆分的收益与代价**：收益是能核对自由文本说明文档（需求说明书点名的「说明文档声称覆盖的类别或时段在样本中缺失」）、整改建议更可执行；代价是模型服务消耗（效率分中权重最高的一项，按名次计分）与输出随机性——因此默认关闭，并以「原文摘录校验 + 多次一致」把随机性挡在结论之外。

### 3.2 编排范式与编排层

- **范式**：`pipeline`（流水线），无模型驱动环节，模型工具白名单为空（子代理只收发文本，不调用工具）。
- **主循环**：发现数据集 → 按质量版本组预分组 → 组内逐数据集执行单数据集检查（依赖拓扑序）→ 组内版本对照 →
  降级共有与参考版本问题 → 不可重推项弃报 → 生成报告与评分 → 全局排序与交付物输出。
- **决策点**（manifest 中 DP1～DP6）：标注族识别、检查适用性、前置依赖、同源版本分组与参考版本、缺陷代码与弃报、汇总与排序；每个决策点写明触发条件、输入输出与失败兜底。
- **并发**：按质量版本组多进程并行，进程数 = min(组数, 容器可用 CPU 数)；组间无共享状态，并行与串行结果逐字节一致。
- **状态与上下文**：每个数据集一个上下文对象（已解析标签、逐检查结论、文件指纹），组内比较结果只在本组进程内可见。

### 3.5 记忆层、插件、运行时与护栏

- **记忆**：数据集上下文与版本组上下文，均为单次运行内的进程内存；不读取任何历史记忆，跨运行持久化不存在，重复运行逐字节一致。
  记忆不是结论来源，每条结论都回查到原始文件。
- **插件**：检查器注册（新增检查即生效）、标注族定义（新数据类型声明即复用通用检查）、模型客户端（默认关闭，供两个子代理使用，逐次计量消耗）。全部随镜像交付，不从外部加载。
- **运行时**：python:3.11.9-slim-bookworm + PyYAML 6.0.2；主进程 + 每组一个工作进程；Docker `--network none`，输入只读挂载。
- **护栏**：只写 `/output`；不访问网络；并行进程数 ≤ 可用 CPU 数；启动与镜像构建时校验规格与实现逐条对应，不一致拒绝运行；
  每个检查的开始、结束、重试、失败、降级写入运行日志；MANIFEST 记录全部输出文件的 SHA-256。

### 3.6 确定性边界

| 环节 | 是否允许模型介入 | 本系统 |
|---|---|---|
| 数据读取、解析、校验 | 不允许 | 确定性程序 |
| 数值计量（比例、偏移、统计量） | 不允许 | 确定性程序 |
| 适用性判定 | 允许，须输出理由 | 确定性程序（DP2），不适用写明原因 |
| 缺陷判定与分类 | 允许，须给出证据位置 | 确定性程序；子代理只抽取文档声明（附原文摘录作证据位置），判定由 D04 程序比对 |
| 严重程度判断 | 允许，须引用规范度量 | 确定性程序（规格 severity_axes） |
| 维度得分与综合排序 | 不允许 | 确定性程序（规格 scoring） |

### 3.7 检查项选择、失败恢复、运行记录与人工介入

- **选择逻辑**：适用 = 用途要求且标注族在适用列表内；不适用 = 整项写明原因；待判定 = 触及受限边界（规范 B.2 逐检查边界表）。
- **失败恢复**：检查器异常 → 重试 1 次 → 仍失败则该单元落待判定，运行日志记「重试」「检查失败」「降级」三个事件，未完成事项说明第七节列出。
- **运行记录**：`run.log.jsonl` 一行一事件：时间戳（UTC）、运行编号、数据集、事件类型、检查编号、实际完成 / 失败原因、耗时、资源峰值、模型消耗（默认 0；启用子代理时按检查记录 token 数）、重试次数。
- **人工介入点**：全部「待判定」进入待复核事项，主要是不可重推项（需外部基准）、图像被改动、使用权限文件缺失、来源固有问题；
  频次见各数据集评分卡的 reviewAndSupplement。判定过程本身不需要人工。

## 4. 质量评价方法

评价规范全文见《数据集质量评价规范（固定版）》，由规格 YAML 自动生成，与实现逐条一致。要点：

1. **缺陷代码**：与附件一污染项目一一对齐（L0-01、L0-03、L2-G、L2-P、L2-T、L2-F、L3-06、L3-07、L3-MIS 为计分轨；
   L2-A、L2-B、L2-C、L2-M（CME）、L1-TS 为不可重推，一律弃报）；E- 开头为需求说明书必检、附件一未单列的补充类型。
2. **四类状态**：通过 / 不通过 / 待判定 / 不适用全量输出；未实现的适用检查落待判定，不从分母移除。
3. **程度计量**：每条结论带程度（度量名、数值、单位、容差）；偏移类按同一形态内两轴归一后 1:1 的严重度（图像：位置偏移、面积比；无框：时间偏移、相对偏差；时序：时间偏移、采样点变化）。
4. **汇总**：12 项缺陷比例 → 6 个维度分 → 综合分；证据不足的维度不计分；关键缺陷单独列示、不可被抵消。
5. **排序**：全部受评数据集全局排序，不并列，写明主要差异来源。
6. **质量预测**：估计缺陷覆盖率并给出预测档位（同组版本数与档位数相同时按组内名次对应）。

### 4.1 公开集验证（对照附件一档位标签）

| 指标 | 结果 |
|---|---|
| 组内排序与档位一致 | 6 组 30 个包全部一致（clean → P1 → P2 → P3 → P4） |
| 预测档位正确 | 30 / 30（同组版本数与档位数相同，按组内名次对应） |
| clean 包上的「不通过」结论 | 0 |
| 缺陷代码不在该包污染项目内的计分轨结论 | 3 条（全部为 AIA / HMI 的 P1 判覆盖不足，占全部计分轨结论的万分之一量级） |
| 附件一特别提醒的误报点 | AIA / HMI 的 P1 报漏标虚标：0；CME 报漏标虚标或边界偏差：0 |
| 不可重推项「不通过」结论 | 0（全部弃报为待判定，写明需补充的基准材料） |
| 效率 | 全量约 12 分钟（6 进程；0.7.0 实测 12 分 21 秒，0.8.0 在服务器高负载时 15 分 41 秒）；镜像 133 MB；单进程峰值内存 1.5 GB；执行失败 0；模型服务消耗 0 |
| 输出规模 | 问题清单 168,326 条（不通过 96,342、待判定 70,693、通过 841、不适用 450 条汇总记录）；运行日志 2,360 个事件 |

各包的估计覆盖率与按缺陷代码的样本数见公开集实测材料 `tier_eval.txt`。

### 4.2 无同源版本时（独立数据集）

隐藏集「含质量变体与独立数据集」。对独立数据集，版本对照不适用，主要靠单数据集判据。借鉴发榜方参考代码（OPC-code）后新增的跨样本一致检查，
在公开集上逐个数据集单独运行的实测（至少有一条计分轨「不通过」结论的样本占比；clean 包误报均为 0）：

| 数据集 | P1 | P2 | P3 | P4 |
|---|---:|---:|---:|---:|
| CME（原有判据 → 加跨样本一致） | 0.1% → 2.4% | 1.2% → 6.9% | 4.8% → 10.9% | 10.3% → 14.9% |
| AIA（原有判据 → 加跨样本一致） | 2.3% → 2.3% | 10.0% → 10.3% | 23.5% → 24.2% | 35.0% → 38.2% |

AIA 的类别错标多数已由「事件类型汇总与明细不一致」（S06）在样本层面判出，跨样本一致检查主要补充到具体事件；CME 帧组一致性提升最明显。
同时修正了单数据集模式的一处误报来源：源事件目录中完全相同的重复事件（各档数量不随污染增加）改列待复核。

## 5. 任务适配方式

- **新数据类型**：在规格 `profiles` 中声明数据类型、数据集类型、识别字段、标注元素路径、类别键、几何键、时间键与身份键；
  通用检查、版本对照、程度计量与排序自动生效。`tools/gen_profile.py` 读样本自动生成草稿并逐项实测命中率（公开集实测：EPB、DMSP、ULF 的草稿与人工编写的配置完全一致；AIA、HMI、CME 的草稿各自是人工配置 hek_image 的子集——人工配置合并了三类的字段），可选用模型补全中文说明，人工审核后写入规格。
- **新检查**：规格中声明编号（类别字母 + 两位序号）、缺陷代码、适用范围与受限边界，并实现同编号检查器；规范文档与构件登记自动重新生成。
- **新用途**：在 `purposes` 中声明，并在检查上标注适用用途。
- **阈值调整**：全部阈值、容差、权重都在规格中，修改后规则版本与规格指纹随之变化，报告可追溯所用版本。
