## 一、本轮的任务

本文件同时规定赛前自测与现场展示两个环节。两者使用同一批数据、同一套校验和：自测的结论即现场陈述的内容，现场不重新发放数据，不要求重新运行。

自测须在 11 月 5 日 12:00 前完成，对 `01_现场展示数据清单.md` 所列 12 个数据目录完成质量评价，得出排序、分数与证据。现场展示在 15 分钟内陈述自测所得的方法与结论。

本轮不向服务器提交计算结果，评价在你的本地环境中完成。现场陈述的对象是你已经跑完的结果，不是现场临时运行。

**三个必交产出**：

| # | 产出 | 时点 |
| -: | --- | --- |
| 1 | 技术方案 PPT，内容条目见第七章 | 11 月 5 日 12:00 前 |
| 2 | `路演结果_{队名}.csv` | 随 PPT 一并提交 |
| 3 | `证据表_{队名}.csv` | 随 PPT 一并提交 |

未按时提交者视为放弃参赛。

本环节三项产出与《交付材料清单》的对应关系：技术方案 PPT 是 DEL-1 方案规划的陈述版；结果表是 DEL-5 评分卡与 DEL-6 排序表的合并简表；证据表是 DEL-7 问题清单与 DEL-8 证据索引的合并简表。正式提交仍按该清单的字段与格式执行，本环节两份 CSV 为现场核对用，取该清单的部分字段。

## 二、运行要求

### 2.1 环境

| 项 | 要求 |
| --- | --- |
| 运行方式 | 本地或自备算力，无网络亦可完成全部检查 |
| 依赖 | Python 3.8 及以上；`numpy`、`Pillow` 可覆盖绝大部分统计 |
| 单目录时限 | 不超过 3 小时 |
| 数据修改 | 不得修改数据目录内任何文件 |

### 2.2 运行记录

每次运行须留存下列记录，供现场问答调取：

| 项 | 内容 |
| --- | --- |
| 运行日志 | 起止时刻、处理对象数、各检查项耗时 |
| 环境 | 操作系统、Python 版本、依赖包版本 |
| 随机种子 | 凡涉及抽样或随机初始化的环节，须记录种子 |
| 复现 | 同一目录重复运行两次，结论逐条一致；出现差异的，说明差异来源与占比 |

### 2.3 现场能力

现场问答环节可能要求就任一目录重跑单项检查。全量重跑不作要求，但单项检查须能在数分钟内复现。

## 三、须给出结论的六个维度

下列六个维度构成本轮评价的框架，名称与顺序与评分标准中评价规范的六维度一致，与《评分口径》的四个计分单元不是同一套划分。

各维度下检查什么、判据从何而来、阈值取多少，由参赛队自行确定并在陈述中说明。其中仅凭数据与标注即可判定的部分，与需外部基准方可判定的部分须分开陈述；缺基准而判不了的，标明判不了并说明所缺何物。

### 3.1 完整性

数据文件与标注文件的对应关系、文件是否可读，以及标注内字段的齐备与自洽。含文件配对、重复标注、文件名与实盘是否一致、字段缺失与取值互相矛盾等。

### 3.2 标注质量

标注内容本身的正确性：类别、位置、范围与目标是否相符，有无漏标与虚标。

### 3.3 样本对应关系

跨文件的关联一致性：标注所指向的对象、标识与路径，是否与数据实盘一一对应。

### 3.4 覆盖与分布

数据集的统计形态，不针对单个文件：空标注比例、目标密度、类别构成，以及时间覆盖是否连续、有无缺口。

### 3.5 文档与来源追溯

随数据下发的说明文档、标注内的来源与版本字段，与数据实际内容是否一致。说明文档描述的是完整 B 榜包，其文件数量与本轮发放范围不同，不属缺陷。

### 3.6 使用条件

该目录可用于什么用途、需何种前置处理。结论按验收、入库、选数分别给出，可多选；同一目录在不同用途下的结论可以不同。每条结论附整改或补查建议，说明处理范围。

## 四、质量分的给出方式

### 4.1 分数口径

对 12 个目录各给一个 `0–100` 分。`100` 表示未发现任何缺陷。

分数须与该目录的缺陷密度单调对应：缺陷占比越高，分数越低。评价完全部目录后，分数不得出现「缺陷多者反而得分高」的情形。

**两套口径的关系**。《评分口径》的四个维度是计分单元，用于把缺陷折算为 `0–1` 的 `q`；第三章的六个维度是检查框架，回答应当检查什么。二者不要求一一对应：按第三章逐项检查，按《评分口径》折算分数。评价的完备性按六维度衡量，分数的量级按四维度对齐。

**缺陷判定的覆盖范围**。第三章六个维度须逐个给出结论，不得留空；判不了的标明 `undetermined` 并说明所缺基准。缺陷类型不以本文件所列者为限，也不以公开口径所列者为限。

公开口径中已列明的类型，逐类给出结论。结论可以是「有，N 处」「无」或「无法判定」，不可留空；判为「无」的，须说明检查范围，否则按未检查处理。公开口径见此前随完整 B 榜包下发的《评分口径》。

公开口径之外、参赛队自行发现的类型，一并报告，说明判据、涉及规模、对下游使用的影响，以及是否计入分数。未说明处置的，不计入分数，仅在证据表中列出。

### 4.2 计分轨与非计分轨

缺陷按五类处理，其中前两类进入分数，后三类不进入：

| 类别 | 内容 | 是否进入分数 |
| --- | --- | --- |
| 标注质量类 | 标注内容的错误：类别、位置、范围、字段值 | 进入 |
| 文件配对类 | 数据与标注的对应关系出错 | 进入 |
| 诊断信息类 | 元数据统计量的偏差，不影响下游使用 | 不进入 |
| 反印证类 | 图像几何变换、加噪等扰动 | 不进入 |
| 数据质量类 | 数值层面的噪声、缺失、越界 | 不进入 |

后三类的异常客观存在，发现后应在证据表中列出，但不计入分数。

### 4.3 排序

须给出两组排序：

| 排序 | 范围 | 要求 |
| --- | --- | --- |
| 数据集内排序 | 每个数据集内 4 个目录 | 名次 1–4，不并列 |
| 全局排序 | 12 个目录 | 名次 1–12，不并列 |

全局排序须跨数据集比较，不得仅在数据集内比较后拼接。排序依据须落到数值，说明主要差异来自哪一类缺陷。不同数据集的样本规模不同，同一类缺陷的绝对条数在数据集之间不具备可比性。

### 4.4 不得代替排序的做法

仅以文件数量作为排序依据的，须在陈述中声明。文件数量差异确实反映配对类缺陷，可将单个数据集内的四个目录按缺陷密度排出次序，但缺陷条数的绝对值受样本规模影响，跨数据集比较时不足以支持全局排序，故该做法不计入方法有效性。

## 五、证据要求

每条结论须携带四项，缺一不予采信：

| 要素 | 内容 |
| --- | --- |
| 缺陷编号 | 形如 `C01-AIA-000123`，由检查编号、数据集与序号组成，全局唯一 |
| 检查编号 | 该条结论对应的检查项编号，与提交的规范一致 |
| 规则版本 | 判定所依据的规则版本号 |
| 证据位置 | 数据目录、文件名、字段路径；图像类缺陷须给区域坐标 |

前三项即《交付材料清单》所称的责任三要素，回答「哪条检查、哪版规则、哪条结论」；证据位置回答结论落在哪个文件。回查时三者与位置须能连成一条链。

证据须可回查：第三方按你给的位置打开文件，应能直接看到所述现象。

现场抽查范围为全部结论的 10%，每队不少于 3 条。

## 六、输出格式

### 6.1 结果表

文件名 `路演结果_{队名}.csv`，UTF-8 编码：

```csv
datasetId,datasetVersion,dirId,rankInDataset,rankGlobal,totalScore,mainDefectTypes,evidence
AIA_AR_sample,v34,AIA_AR_sample_z4h764sf2d,1,1,96,"文件配对","配对差异 0 处；尺寸字段与图像一致"
AIA_AR_sample,v34,AIA_AR_sample_7qn2pdeube,2,4,88,"文件配对；类别置换","配对差异 N 处；类别异常 N 处"
AIA_AR_sample,v34,AIA_AR_sample_3mogtggl50,3,8,79,"文件配对；类别置换","配对差异 N 处；类别异常 N 处"
AIA_AR_sample,v34,AIA_AR_sample_p86y2cz08y,4,12,68,"文件配对；类别置换","配对差异 N 处；类别异常 N 处"
```

`N` 为占位，填写实测数量。名次与分数为格式示意，不是你的结论。

| 列 | 含义 |
| --- | --- |
| `datasetId` | 数据集名 |
| `datasetVersion` | 数据版本，本批统一填 `v34` |
| `dirId` | 目录名，含随机后缀，完整 |
| `rankInDataset` | 数据集内名次，1–4 |
| `rankGlobal` | 12 个目录的全局名次，1–12 |
| `totalScore` | 0–100，整数或一位小数 |
| `mainDefectTypes` | 主要缺陷类型，分号分隔 |
| `evidence` | 一句话，给出关键数量 |

六维度得分与排序依据在陈述中给出，不占本表列位。

### 6.2 证据表

文件名 `证据表_{队名}.csv`，UTF-8 编码：

```csv
findingId,checkId,ruleVersion,dirId,objectId,fieldPath,locatorType,verdict,detail
C01-AIA-000123,C01,v1.0,AIA_AR_sample_p86y2cz08y,,,file,fail,"标注文件 1838，数据文件 1817，差异 21"
C07-AIA-000045,C07,v1.0,AIA_AR_sample_p86y2cz08y,2RZxiDO_2nEA_OcTL4p9,hek_event_annotation.matched_events[0].concept,annotationRecord,fail,"类别为 Coronal Hole，与数据集定位不符"
```

| 列 | 含义 |
| --- | --- |
| `findingId` | 缺陷编号，与第五章一致 |
| `checkId` | 检查项编号，形如 `C01`，两位序号 |
| `ruleVersion` | 规则版本 |
| `dirId` | 目录名 |
| `objectId` | 对象标识；目录级结论留空 |
| `fieldPath` | 字段路径；不适用时留空 |
| `locatorType` | `file` / `sampleId` / `annotationRecord` / `imageRegion` / `timeInterval` |
| `verdict` | `pass` / `fail` / `undetermined` / `not_applicable` |
| `detail` | 现象描述与数值 |

四类状态须全量输出。某一检查项只列 `fail` 而无 `pass`、`undetermined`、`not_applicable` 记录的，视为该项未检查完成。

`undetermined` 用于判定条件不满足、无法给出结论的检查项。如实标注不扣分；写成 `pass` 而实际未检查，将在抽查中暴露。

## 七、技术方案 PPT 的内容条目

技术方案 PPT 是现场陈述的载体。下表列出可包含的内容条目，供组织材料时参照。页数、顺序与呈现形式不作统一要求。

PPT 中出现的分数、名次、缺陷条数须与提交的两张 CSV 一致。

| # | 内容 | 条目 |
| -: | --- | --- |
| 1 | 方案总览 | 系统面向的问题；整体组成；各部分职责与相互关系 |
| 2 | 智能体架构 | 分层结构；各层的职责及其输入输出；模型承担的判断与规则承担的判断如何划分；数值计量与分数汇总由哪一环节执行（不得由模型直接给出分数与名次）；关键环节的数据流向 |
| 3 | 工作流程 | 端到端阶段划分；各阶段的输入与输出；单目录的执行方式；可并行与须串行的安排；耗时与资源占用；人工复核介入的位置 |
| 4 | 质量标准 | 各检查项的判据来源；阈值的确定方式；指标的分子与分母；各维度结论汇总为分数的方式；规范所写规则与代码行为的一致性；重复运行的稳定性 |
| 5 | 多元多模态适配（泛化性） | 已覆盖的数据来源、模态与结构类型；不同模态（图像、掩膜、时序表格、事件表）的差异识别方式与处理位置；跨数据集复用的部分与单独实现的部分；换一类数据源或新增一种模态需改动的部分；数据集特有常量的存放方式 |
| 6 | 结果与排序 | 12 个目录的分数；数据集内名次与全局名次；排序差异的主要来源 |
| 7 | 典型缺陷 | 各数据集的缺陷实例；目录与文件名；字段路径或区域坐标；判定现象与依据 |
| 8 | 场景支持 | 验收、入库、选数等场景下的判定线与处置建议 |
| 9 | 局限与改进 | 无法判定的检查项及原因；所缺的基准；后续改进方向 |

## 八、允许与不允许

**允许**

1. 编写脚本做统计、可视化、阈值判定。
2. 训练缺陷检测模型，使用公开数据集或预训练模型。
3. 调用大模型辅助判断，记录消耗量。
4. 查阅公开文献与字段定义，引用时注明来源。
5. 声明某项检查判不了，并说明缺什么基准。

**不允许**

1. 修改数据目录内任何文件。
2. 与其他参赛队交换数据或结论。
3. 使用任何来源的标准答案、缺陷位置清单或注入参数。
4. 将未实际执行的检查写成 `pass`。
5. 在分数与排序中使用未在证据表中列出的结论。

## 附、名词解释

| 术语 | 解释 |
| --- | --- |
| 数据集 | 一批同源观测对象及其标注的集合，以 `datasetId` 标识。本轮三个数据集的构成见 `01_现场展示数据清单.md` |
| 目录 | 数据集内一次加工形成的完整数据与标注集合，以 `dirId` 标识。同一数据集的目录之间对象互不重叠 |
| 对象 | 一个数据文件及其对应标注构成的单位。图像类为一张图，时序类为一个时段 |
| 标注文件 | 记录对象标注内容的 JSON 文件，与数据文件一一对应 |
| 标注目标 | 标注文件内记录的一个待检实体。图像类为一个多边形框或掩膜，时序类为一个时间区间 |
| 多边形框 | 以若干顶点坐标围成的闭合区域，用于标出图像中目标的边界 |
| 掩膜 | 与多边形框同义，指以闭合多边形标出的区域；一个标注文件可含多个掩膜 |
| 配对 | 使数据文件与标注文件建立一一对应关系的过程 |
| 缺陷 | 数据或标注中偏离应有状态的记录，可定位到具体文件与字段 |
| 判据 | 判定某一现象是否构成缺陷所依据的规则或事实来源 |
| 阈值 | 判据中用于区分合规与违规的数值界限 |
| 分母 | 计算比率时的基数。分母须可在数据上一次数清，且不因缺陷存在而改变 |
| 计分轨 | 计入质量分的缺陷类别 |
| 非计分轨 | 客观存在但不计入质量分的异常类别，含诊断信息、反印证、数据质量三类 |
| 诊断信息 | 描述数据统计特征的元数据偏差，不影响下游使用 |
| 反印证 | 对图像做几何变换或加噪等处理，图像与标注仍保持一致 |
| 可判定 | 仅凭数据与标注即可得出结论，无需外部基准 |
| 不可判定 | 须外部基准方可下结论的项目，应标注 `undetermined` |
| 倒挂 | 质量较差的对象得分高于质量较好者，或名次与缺陷密度相反 |
| 复现 | 同一输入重复运行，得到逐条一致的结论 |
| 模态 | 数据的呈现形式。本轮含图像、掩膜、时序表格与事件表四类 |
| 缺陷编号 | 结论的全局唯一标识，形如 `C01-AIA-000123` |
| 责任三要素 | 缺陷编号、检查编号、规则版本三项，回答哪条检查、哪版规则、哪条结论 |
| 证据位置 | 结论所指向的目录、文件与字段路径。图像类缺陷须给区域坐标 |
