# 演示视频 · 录制全过程与逐镜头脚本（正式版，≤ 5 分钟）

对应交付物 DEL-12：MP4（H.264），不超过 5 分钟。成片目标 **4 分 40 秒**，留 20 秒余量。
本文按「准备 → 预演 → 配音 → 分段录制 → 剪辑 → 导出检查 → 放入提交包」的顺序写，照做即可。
另有两份专题脚本（`演示视频脚本-模型子代理.md`、`演示视频脚本-参考代码借鉴.md`），只在需要更长的补充视频时使用；本片已把两者的要点各压缩成一句。

## 三、录制方法

1. **先配音，后录画面**：把下文每个镜头的旁白逐字稿先录成音频，得到每段的准确时长；再按时长录画面，剪辑时对齐。
2. **分镜头单独录**：每个镜头一个视频文件，命名 `01_开场.mov`、`02_思路.mov`……；每段录 2～3 遍，挑最顺的一遍。
3. **终端等待可以加速**：命令运行的等待在剪辑时加速或剪掉，但保留输出结果。
4. **操作放慢**：鼠标移动和翻页比平时慢一倍；需要观众看清的地方停 2 秒。

## 四、逐镜头脚本

时长为成片中的时长。「画面与操作」按顺序执行；「强调」是剪辑时加框、放大或字幕的位置；「旁白」照读。

### 镜头 1 · 开场（0:00–0:15，15 秒）

- **画面与操作**：PPT 封面页。
- **强调**：标题「空间科学智能就绪数据集质量评价智能体」。
- **旁白**：
  > 数据中心每天要决定一批科学数据收不收。我们做的智能体，能自动检查、定位问题、给数据集打分排序，而且每一条结论都能被第三方复算。

### 镜头 2 · 问题与思路（0:15–0:40，25 秒）

- **画面与操作**：翻到 PPT「需求理解」页，停 8 秒；再翻到「方案总览」页。
- **强调**：「判据来自数据之外」「五步流水线」。
- **旁白**：
  > 难点在于科学数据没有标准答案。我们的判据来自数据之外：标签自己的声明、物理关系，以及同一份数据的不同质量版本互相对照。全部判定由确定性程序完成，大模型默认不调用，所以结论可以复算，模型消耗为零。

### 镜头 3 · 现场运行（0:40–1:15，35 秒）

- **画面与操作**：终端里依次输入（每条回车后停 1 秒）：

```bash
ssh sqa
```

```bash
cd /data/sqa/demo-video && ls data
```

```bash
docker images | grep sqa-agent
```

```bash
docker run --rm --network none -v $PWD/data:/data:ro -v $PWD/out-a:/output sqa-agent:0.8.0
```

```bash
cut -d, -f1,2,4 out-a/05_排序表/ranking_global.csv
```

- **强调**：`--network none`（断网）；镜像大小 133 MB；运行约 5 秒；排序表第 1 名是 `aaue04ws6s`（clean），最后一名是 `96mfosyutr`（P4）。
- **旁白**：
  > 这是极光数据的五个质量版本。镜像只有 133 兆，断网运行，一条命令、五秒钟跑完。系统自动认出它们是同一份数据的不同版本，互相对照。排序从干净版本到污染最重的版本，和发榜方公布的档位完全一致。

### 镜头 4 · 评分卡（1:15–1:50，35 秒）

- **画面与操作**：浏览器打开素材 `DMSP_SSUSI_96mfosyutr_*.html`，从上往下慢慢滚动。
- **强调**：「综合分 89.28」「质量预测：最接近档位 P4」「检查覆盖」「四类状态」；滚到「缺陷程度」表，框出「缺失比例 31 / 286」；再滚到「主要缺陷及影响」的整改建议一列。
- **旁白**：
  > 每个数据集一份评分卡：六个维度的得分、综合分、预测的污染档位，以及通过、不通过、待判定、不适用四类检查的数量。每个缺陷指标都写明分子分母，比如缺失比例是 286 个样本里缺 31 个。每类问题都附有整改建议。

### 镜头 5 · 抽查一条结论（1:50–2:30，40 秒）

- **画面与操作**：
  1. 终端（仍在服务器上）运行，生成抽查页：

```bash
python3 /data/sqa/agent-next/tools/show_evidence.py out-a data X06-DMSP_SSUSI_96mfosyutr-000043 --out 抽查.html
```

  2. 切到浏览器，打开素材 `抽查-X06-DMSP_SSUSI_96mfosyutr-000043.html`（与刚生成的页面内容相同，事先已下载）。
  3. 依次停在「① 结论」「② 证据索引」「文件校验值与证据索引一致：是」，最后滚到「③ 原始文件」的放大图。
- **强调**：结论编号、缺陷代码「L2-G 边界与位置偏差」、程度里的「offset_px 51.096」；放大图上**黄框（本版本）与青色虚线（参考版本）**的位移。
- **旁白**：
  > 评委可以任选一条结论当场核对。输入结论编号，回查链的每一环都在这一页：结论、证据位置、文件校验值，最后是原始图像。黄框是这个版本的标注，青色虚线是参考版本里的同一个目标，偏移了五十一个像素，系统判为边界与位置偏差，并给出偏移量和面积比作为严重程度。

### 镜头 6 · 复算与重跑一致（2:30–3:00，30 秒）

- **画面与操作**：
  1. 回到评分卡，指向维度表里的「完整性 93.49648」，再指向缺陷程度表里的「缺失比例 0.108392」「损坏与数据改动比例 0」。
  2. 剪辑时叠加字幕算式：`100 × (1 − 3 × 0.108392 ÷ (3 + 2)) = 93.50`（缺失比例权重 3，损坏比例权重 2，见评价规范第 2 节）。
  3. 终端再跑一遍到另一个目录并比较：

```bash
docker run --rm --network none -v $PWD/data:/data:ro -v $PWD/out-b:/output sqa-agent:0.8.0 2>/dev/null && diff -rq out-a out-b | grep -v -E "run.log.jsonl|run_summary.json|00_MANIFEST.yaml"
```

- **强调**：算式结果与评分卡一致；`diff` 没有任何输出。
- **旁白**：
  > 得分可以手算：完整性维度按规范里的公式，一百乘以一减去加权缺失比例，正好是九十三点五。再重跑一次，除了带时间戳的运行日志，所有结果逐字节相同。

### 镜头 7 · 公开集全量与档位检验（3:00–3:30，30 秒）

- **画面与操作**：先翻到 PPT「实测效果 · 公开集全量」页，停 6 秒；再打开素材 `档位标签检验-0.8.0.txt`，滚到最后一行。
- **强调**：PPT 上「12 min」「133 MB」「模型服务消耗 0」；文本末行「组内排序与档位一致：是；clean 包上的不通过结论 0 条」。
- **旁白**：
  > 公开集全部三十个数据集、十二万多个样本，一次运行约十二分钟，不用加速卡。我们用发榜方公布的档位标签逐包检验：三十个包的排序全部一致，干净版本上没有一条误报。

### 镜头 8 · 判不了的不乱报（3:30–3:55，25 秒）

- **画面与操作**：打开 `交付物/提交包/09_未完成事项说明.md`，滚到「四、不可重推检查项声明」的表格。
- **强调**：表格中「L2-B 结构参数失配 · 需补充 CDAW 目录中的质量、速度、动能 · 弃报 2048 条」；字幕补一条结论原文：「本项判不了，需补充基准材料（结构参数失配）」。
- **旁白**：
  > 发榜方列出的五类需要外部基准才能判定的问题，比如日冕物质抛射的质量、速度、动能对不上，我们一条「不通过」都不报，统一写明「本项判不了」以及需要补充什么材料。判不了就说判不了。

### 镜头 9 · 没有同源版本时（3:55–4:20，25 秒）

- **画面与操作**：翻到 PPT「交付与实施计划」页，停在「风险与预案」第一条；再翻到「关键技术路线」页第一层。
- **强调**：「同一事件跨样本一致」「CME 单独运行检出样本 P2 1.2% → 6.9%，clean 零误报」。
- **旁白**：
  > 隐藏集里还会有没有同源版本的独立数据集。我们借鉴发榜方给的参考代码，加入了同一事件跨样本一致的检查：日冕物质抛射三帧一组，标注应当相同。单独运行时检出明显提高，干净数据仍然零误报。

### 镜头 10 · 规范与实现一致、收尾（4:20–4:40，20 秒）

- **画面与操作**：终端运行下面的命令，然后切回 PPT 封面：

```bash
docker run --rm sqa-agent:0.8.0 validate-spec
```

- **强调**：输出「规格 0.8.0 有效：45 项检查，已实现 43 项，待实现 2 项」。
- **旁白**：
  > 评价规范和程序来自同一份判定标准，启动和构建时都会逐条校验：规范写什么，程序就做什么。谢谢观看。

## 五、剪辑

1. 按镜头顺序把配音放到音轨，再把对应画面放到视频轨；画面长于配音的部分剪掉或加速。
2. 关键位置加强调（红框或放大，停留不少于 2 秒）：镜头 3 的排序表、镜头 4 的「31 / 286」、镜头 5 的黄框与青色虚线、镜头 6 的算式与空的 `diff` 输出、镜头 7 的末行。
3. 字幕：用剪映「识别字幕」，再逐句对照逐字稿校对；数字与编号（如 `X06`、`L2-G`、`89.28`）必须准确。
4. 不加片头动画；片尾停在 PPT 封面 2 秒。
5. 总时长 ≤ 4:50；超时就先压缩镜头 2 和镜头 9。
