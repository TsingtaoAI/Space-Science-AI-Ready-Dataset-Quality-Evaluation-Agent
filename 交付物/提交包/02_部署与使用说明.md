# 部署与使用说明 · 空间科学智能就绪数据集质量评价智能体

> 系统版本 0.8.0 ｜ 规则版本 0.8.0 ｜ 对应交付物 DEL-3

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | 任意可运行 Docker 的 Linux x86_64 主机（已在 Ubuntu 22.04 验证） |
| Docker | 20.10 及以上 |
| CPU / 内存 | 至少 1 核、2 GB；全量公开集（30 个数据集）建议 6 核、8 GB（6 进程并行，单进程峰值约 1.5 GB） |
| 加速卡 | 不需要（DCU 与 A10 服务器均可运行，不使用加速卡） |
| 网络 | 不需要；运行时以 `--network none` 断网运行 |
| 磁盘 | 镜像约 133 MB；输出约为输入标签体积的 1～2 倍（全量公开集约 0.7 GB） |
| 模型服务 | 默认不需要（模型服务消耗 0）；`--use-llm` 时使用评测平台提供的 OpenAI 兼容模型服务（第 2 节） |

## 2. 镜像加载与启动

离线环境中只需镜像文件，不需要任何网络下载：

```bash
docker load -i sqa-agent-0.8.0.tar.gz
```

```bash
docker run --rm --network none -v /path/to/datasets:/data:ro -v /path/to/output:/output sqa-agent:0.8.0
```

完整的离线启动命令（指定用户，避免输出文件属主为 root；指定并行进程数）：

```bash
docker run --rm --network none --user "$(id -u):$(id -g)" -v /path/to/datasets:/data:ro -v /path/to/output:/output sqa-agent:0.8.0 run --input /data --output /output --workers 6
```

启用模型子代理（模型服务由评测平台提供，地址、密钥、模型名以环境变量注入；运行仍不访问其他网络）：

```bash
docker run --rm -e LLM_BASE_URL -e LLM_API_KEY -e LLM_MODEL -v /path/to/datasets:/data:ro -v /path/to/output:/output sqa-agent:0.8.0 run --input /data --output /output --use-llm
```

模型只读说明文档（数据集目录中的 README、*.md、*说明*）并改写整改建议，不参与判定与计分；消耗逐检查记入运行日志的 tokenUsage，合计见 run_summary.json。

校验规格与实现逐条对应（镜像构建时已执行一次）：

```bash
docker run --rm --network none sqa-agent:0.8.0 validate-spec
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `--input` | 输入目录：单个数据集，或包含多个数据集的目录 | `/data` |
| `--output` | 输出目录（唯一可写位置） | `/output` |
| `--workers N` | 并行进程数；0 = 自动（容器可用 CPU 数与质量版本组数中较小者） | 0 |
| `--purpose` | 评价用途：`ingest` 入库 / `training` 选数 | `ingest` |
| `--use-llm` | 启用两个模型子代理：读说明文档供 D04 比对、改写评分卡整改建议（需 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，缺失即以退出码 5 终止） | 关闭 |

退出码：`0` 完成（「拒绝入库」也是正常结果）· `2` 规格错误或规格与实现不对应 · `3` 输入目录错误 · `4` 覆盖率不变量破坏 · `5` 模型环境变量缺失。

## 3. 输入数据规格

- 一个数据集 = 一个目录，每个样本一份 JSON 标签 + 一个数据文件，按文件名配对：
  - 分目录布局：`<数据集>/label/<数据文件名>.json` + `<数据集>/data/<数据文件名>`（HMI、AIA、CME）
  - 平铺布局：`<数据集>/<id>.json` + `<数据集>/<id>.png`（DMSP、EPB），或 `<数据文件名>.json` + 数据文件（ULF）
- 标注族按标签内容识别（不依赖目录名）：HEK 事件（`hek_event_annotation`）、ULF 事件（`ulf_event_annotation`）、
  极光矩形（`science_annotation.specialShapes`）、等离子体泡分割（`science_annotation.mask`）。
- 同一基础数据的多个质量版本同时放在输入目录下时，自动启用质量版本对照（同标注族、样本名 Jaccard ≥ 0.5 归为一组）。
- 识别不出标注族的标签不会被跳过：相关检查落「待判定」并写明缺少的标注块。
- 数据集根目录若带 `file_list.txt`（文件清单）与 `dataset_summary.json`（数据集摘要）：二者不当作样本，文件清单由 P04 与实际文件核对，摘要作为说明文档供 D04 读取（发榜方参考代码显示源端数据集带这两个文件）。

## 4. 输出产物说明

| 路径 | 内容 |
|---|---|
| `00_MANIFEST.yaml` | 本次输出全部文件的字节数与 SHA-256、运行编号、数据集列表 |
| `03_评价规范.yaml` | 本次运行所依据的规格（与镜像内规格逐字节相同） |
| `04_评分卡/<数据集>_<版本>.json`、`.html` | 逐数据集评分卡：六维度得分、覆盖率、四类状态计数、主要缺陷（回指结论编号）、关键缺陷、质量预测、证据编号 |
| `05_排序表/ranking_global.csv` | 全局排序，名次 1..n 连续不并列，`comparisonBasis` 写明主要差异来源 |
| `06_问题清单/findings.jsonl` | 问题清单（权威）：四类状态全量输出；每条带结论编号、检查编号、规则版本、缺陷代码、证据编号、程度计量 |
| `07_证据索引/evidence_index.csv` | 证据编号 → 定位类型、可直接打开的位置、文件校验值、产生它的运行编号；`evidence/` 为证据内容 |
| `08_运行日志/run.log.jsonl` | 一行一事件：每个检查的开始、结束、重试、失败、降级，UTC 时间戳、耗时、资源峰值、模型消耗、重试次数 |
| `08_运行日志/system_env.txt`、`seeds.yaml` | 系统版本、规则版本、规格指纹、运行环境；随机种子（固定 0，判定不使用随机数） |
| `09_未完成事项说明.md` | 未实现检查、未覆盖维度、不可计算项、不可重推检查项声明、已知局限 |
| `details/<数据集>/report.json` | 完整判定记录（全部证据与中间量，供复算） |

## 5. 典型运行示例

公开集全量（30 个数据集、123,565 个样本），服务器断网容器：

```bash
docker run --rm --network none --user "$(id -u):$(id -g)" -v /data/sqa/extract/publish:/data:ro -v /data/sqa/out:/output sqa-agent:0.8.0
```

标准错误输出逐个数据集打印进度与结论，例如：

```
[变体组] AIA_AR_sample_2wf6w5morj / ... ：样本 3150，可确认参考 3150
[AIA_AR_sample_zar6xq3d6q] 标记后入库 · 已检 35 项 / 适用 35 项 / 检出 0 项 · 质量分 100.0
```

单个数据集（无同源版本，版本对照判「不适用」并写明原因，其余检查照常）：

```bash
docker run --rm --network none -v /path/to/one_dataset:/data:ro -v $(pwd)/out:/output sqa-agent:0.8.0
```

## 6. 现场抽查一条结论

```bash
python3 tools/show_evidence.py /path/to/output /path/to/datasets B03-HMI_AR_sample_ykt33mm8o2-000008 --out 抽查.html
```

生成一页 HTML：结论、证据索引、文件校验值是否一致，原图上标出证据区域（时序数据画出曲线与区间），以及标签中该位置的原文。只用 Python 标准库。

## 7. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 退出码 3「输入目录下没有可识别的数据集」 | 输入目录层级过深（最多 3 层）或没有标签 JSON；把 `-v` 挂载到数据集的上一级 |
| 输出文件属主为 root | 加 `--user "$(id -u):$(id -g)"` |
| 运行较慢 | 用 `--workers` 指定与可用 CPU 数相当的进程数；日志几分钟不更新属正常（组内版本对照阶段） |
| 运行日志中有「检查失败」「降级」事件 | 某检查器在个别单元上异常，已按重试上限处理并落「待判定」，原因写在事件的 status 字段，见 `09_未完成事项说明.md` 第七节 |
| 退出码 2 | 规格被改动后与实现不对应；恢复镜像内规格或重新构建镜像 |
