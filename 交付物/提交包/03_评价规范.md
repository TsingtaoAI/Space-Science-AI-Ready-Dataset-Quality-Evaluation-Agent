## 4. 四类检查状态与证据分母

| 状态 | 含义 | 计入已完成 | 计入适用分母 |
|---|---|---|---|
| 通过（`pass`） | 满足要求 | 是 | 是 |
| 不通过（`fail`） | 已确认缺陷 | 是 | 是 |
| 待判定（`pending`） | 依据不足；必须写明缺什么材料 | 是 | 是 |
| 不适用（`not_applicable`） | 与本数据类型或用途不适用；注明原因 | 否 | 否 |

- 完成率 = 已完成检查 / 适用检查；**未实现的适用检查落「待判定」，不得从分母移除**。
- 覆盖率写成「已检 N 项 / 适用 M 项 / 检出 K 项」，每次运行断言 `defects(K) <= completed(N) <= applicable(M)`，不成立即以退出码 4 终止。
- 「不适用」必须写明原因（用途不要求、标注族不适用、无同源版本可对照）。
- 「待判定」必须写明缺少的材料与补查要求，进入待复核清单，出口为人工复核。
- 检查器执行异常时按 `execution.retry_limit`（1 次）重试，仍失败则对相关单元落「待判定」并记入运行日志与未完成事项说明。

## 5. 汇总方法（样本结果 → 指标 → 维度 → 综合分）

1. **指标**：按第 2 节的分子、分母计算比例 r。
2. **严重度因子** f：位置/边界偏移取 `0.5 + 0.5 × 偏移元素平均严重度`，其余指标 f = 1。
3. **维度分**：`S_d = 100 × (1 − Σ w_k·r_k·f_k / Σ w_k)`，k 取该维度下可计算的指标。
4. **综合分**：`S = Σ W_d·S_d / Σ W_d`，d 取有得分的维度。
5. **等级**：自上而下匹配，同时满足分数下限与关键缺陷比例上限（**暂定**：未获取档位标签文件，阈值未经标定）：

| 等级 | 综合分下限 | 关键缺陷比例上限 |
|---|---:|---:|
| 高 | 95 | 0.01 |
| 中 | 85 | 0.1 |
| 低 | 0 | — |

**质量预测**：至少有一条计分轨「不通过」结论的样本占比作为估计缺陷覆盖率，取最接近的档位锚点（附件一 A2）：clean 0%，P1 5%，P2 20%，P3 40%，P4 60%。同源版本组的版本数与档位数相同时，按组内名次一一对应档位（同组各版本分属不同档位）。评分卡 qualityPrediction 给出估计值、预测档位与所用方法。

报告中给出每一步的中间量（`quality.measures`、`quality.terms`、`quality.dimensions`），第三方可由检查结果与本规范独立复算。

### 严重度（同一形态内两轴归一后 1:1）

| 形态 | 轴 1 | 轴 2 |
|---|---|---|
| image | position_offset：min(1, 中心偏移像素 / sqrt(参考外接框面积)) | area_ratio：min(1, |ln(面积比)|) |
| time | time_offset：min(1, 起止时刻最大偏移秒 / 3600) | relative_deviation：min(1, 偏移 / 参考时长) |
| timeseries | time_offset：min(1, 声明起止时刻偏移秒 / 3600) | sample_points：min(1, |采样点增删| / 参考点数) |

## 6. 关键缺陷

关键缺陷 = 下列严重度为「关键」的检查判出的缺陷：S01 标签 JSON 严格可解析、S02 顶层类型为对象且可识别标注族、P01 标签引用的数据文件存在、P02 标签内文件名与标签文件名一致、P04 文件清单与实际文件一致、M03 事件身份标识与同批格式一致（疑似虚构标注）、C05 同一事件在不同样本中的类别一致、B05 同一事件在不同样本中的时刻一致、X01 样本相对同源版本整体缺失、X03 类别与参考版本一致（类别错标）、X04 无漏标（相对同源版本）、X05 无虚标（相对同源版本）、X06 位置/边界无偏移（相对同源版本）。

- 在评分卡与报告中**单独列示**：受影响样本数、比例、各检查的缺陷数。
- **不可被其他维度抵消**：关键缺陷比例超过某等级上限的数据集，无论综合分多高都不能评为该等级。
- 入库结论：任一关键检查不通过即「拒绝入库」。

## 7. 可比组与排序

- **可比组**：同一标注族、样本名集合 Jaccard ≥ 0.5 的数据集视为同源质量版本，归为一组；无同源版本的数据集以标注族为比较组。
- **组内排序**：按综合分降序。
- **全局排序**：全部受评数据集按综合分降序；同分依次比较关键缺陷单元数（少者优）、最大单项比例（低者优）、数据集标识，**不输出并列**。每个名次给出主要扣分因素与领先下一名的原因。
- **保留分项比较的条件**：相邻两名综合分差小于 0.5 分时，排序表标注「差异不显著」，比较以分维度得分为准。
- **不同规模、分辨率、覆盖范围**：所有指标均为比例；位置偏移按目标尺度归一，时间偏移按事件时长归一，因此规模与分辨率不同的数据集可比。

## 8. 证据不足的处理

- 某指标相关检查全部不适用或分母为 0 时，该指标「不可计算」，从维度分的分子分母中同时移除。
- 某维度下没有可计算指标时，维度标为「证据不足」，**不按 0 分或满分计入综合分与排名**。
- 质量变体对照只有 2 个版本，或没有多数版本时，差异只落「待判定」，不判缺陷。

## 9. 质量变体对照

公开集实测：同一组质量版本的样本同名一一对应，注入缺陷在质量档之间**部分嵌套**（同一缺陷常出现在 3 个以上较差版本中），因此不能简单以多数版本为参考。参考选择规则：

1. **质量序**：按下列独立检查（不依赖版本对照）的不通过单元数给组内版本排序，越少越靠前：S01、S02、S03、S05、S06、P01、P02、V01、V02、V03、C01、C02、C04、B01、B03、B04、V04、N03、D01、D02。
2. **有效性**：某版本该样本的记录被独立检查判为不通过，其内容不能作参考。
3. **参考**：取质量序最靠前、内容有效的版本；若它孤立且另有内容获 3 个以上版本支持，落「待判定」。
4. **版本不足**：参与比较的版本少于 3 个时，差异一律落「待判定」。
5. **共有问题降级**：同一样本在所有同源版本中都被同一检查判为不通过，属基础数据特性而非版本缺陷，降级为「待判定」。
6. **参考版本问题降级**：参考版本（质量序第一）同一样本、同一位置、同一判据也不通过的单数据集结论，属来源固有问题，降级为「待判定」（附件一：clean 档注入覆盖率 0%，源数据本已存在的问题不计入任何档位）。
7. **未匹配元素配对**：同一样本内参考与本版本都剩有未匹配元素时，身份字段相同、或两侧都无身份字段且数量相等的，一一配对判为偏移（X06），不拆成一漏一虚；身份不同的仍分别判漏标、虚标。
8. **几何变化细分**：外接框中心偏移 < 0.1（按目标尺度归一）且 |ln 面积比| ≥ 0.15 判为覆盖不足/过度（L3-MIS），其余几何偏移判为边界与位置偏差（L2-G），时间偏移判为时段起止抖动（L2-T）；L3-MIS 只对 hek_image 启用。

标注元素先按身份字段配对，再配完全相同者，最后按「中心距离/目标尺度 + 时间偏移/时长 + 其余属性差异比例 + 类别差异 0.3」贪心配对，代价 > 2.0 视为不同目标。同一路径已被单数据集检查判出的缺陷，变体对照不重复报告。

## 10A. 模型服务的使用边界（可选，默认关闭）

默认不调用任何模型（模型服务消耗 0）。只有 `--use-llm` 时，按评测平台注入的 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 启用两个子代理；两者都不做计量、判定、计分与排序（交付材料清单 §6.7）：

| 子代理 | 做什么 | 约束 | 进入结论的方式 |
|---|---|---|---|
| doc_claim_extractor | 从说明文档（README*、readme*、*.md、*.rst、*说明*.txt、*说明*.md、dataset_summary*.json）抽取可核对的声明：sample_count、categories、time_range、image_size、modality | temperature 0；每条声明须附逐字出现在文档中的原文摘录，否则丢弃；同一文档调用 2 次，只采用完全一致的声明，不一致落待判定；单个文档最多 20000 字符 | 只作为 D04 的输入，比对与判定由确定性程序完成 |
| remediation_writer | 把评分卡主要缺陷的整改建议改写得更具体 | 只改写表述，不得给出分数或结论 | 只写入评分卡 remediationDetail 字段，不影响任何结论与分数 |

D04 的比对容差：样本数相对偏差 > 0.01；声称时段超出数据实际起止 > 86400 s。没有说明文档 → 不适用；有文档但未启用模型 → 待判定。提示词写在规格 `llm.prompts` 中，随规则版本固定。

## 11. 输出与可复核

输出目录结构按《交付材料清单》§三：`04_评分卡/`（每数据集 JSON + HTML）、`05_排序表/ranking_global.csv`、`06_问题清单/findings.jsonl`（四类状态全量输出，结论以此为准）、`07_证据索引/evidence_index.csv` 与 `evidence/`、`08_运行日志/run.log.jsonl`、`system_env.txt`、`seeds.yaml`、`09_未完成事项说明.md`、`00_MANIFEST.yaml`；`details/` 下为完整判定记录。

- 每条结论携带 检查编号、规则版本、证据位置（文件 / 样本 / JSON 路径 / 图像区域 / 时间区间），并给出缺陷代码与程度计量。
- 结论编号 `<检查编号>-<数据集>-<序号>`，证据编号 `EV-<结论编号>`；证据索引给出定位类型、可直接打开的位置与文件校验值。

- 文件清单记录每个文件的字节数与校验值，数据集版本 = 清单的 SHA-256；运行编号由系统版本、规格指纹与全部数据集版本确定。
