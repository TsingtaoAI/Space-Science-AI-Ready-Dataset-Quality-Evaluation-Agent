# 设计说明

每条设计都对应赛题说明里的一条要求。

## 1. 判定流程

```
发现数据集 → 读规格 → 校验规格与实现对应 → 按依赖拓扑排序
  → 逐项检查：用途适用？ → 模态适用？ → 前置检查通过？ → 执行
  → 四态汇总 → 覆盖率不变量 → 三档结论 → 质量分 → 排序
```

检查按「语法层 → 类型层 → 字段层 → 语义层」分层，对应赛题的三种典型异常：

| 层 | 检查 | 典型异常 |
|---|---|---|
| 语法 | S01 严格解析（拒绝 NaN、重复键、非 UTF-8；解析失败不当作空对象） | JSON 无法解析 |
| 类型 | S02 顶层为对象；S03 字段类型 | 结构类型不符 |
| 语义 | P02 标签编号 = fileName 编号；D01 采样率 × 时长 = 点数 | 文件错配 |

## 2. 四种状态与分母

- 前置检查未通过的记录，后续检查落「待判定」并写明先修什么，不会静默跳过。
- 规格里声明了、但代码还没实现的适用检查（`implemented: false`），运行时落「待判定」并带 `missing_materials`，**不从分母删除**。
- 「不适用」必须带原因：按用途（如入库不要求 R01）或按模态（时序数据集不查像素框）。
- 模态无法确定时，模态相关的检查落「待判定」，不默认为「不适用」。
- 每次运行都断言 `K ≤ N ≤ M`，违反时退出码为 4，不输出看起来完整的报告。

## 3. 三档结论

由规格中的 `verdicts` 声明，按顺序匹配：critical 不通过 → 拒绝入库；critical 待判定，或 major 不通过 → 转人工复核；其余 → 标记后入库。
`basis_checks` 列出触发结论的检查编号。

## 4. 可复算与确定性

- 除 `08_运行日志/run.log.jsonl`、`run_summary.json` 与 `00_MANIFEST.yaml` 外，全部输出没有时间戳和耗时，列表都排了序，同一输入和规则版本重跑逐字节一致（有测试覆盖）。
- 报告记录 `spec_sha256`，评分卡写明规范版本与运行编号，第三方可确认用的是同一份规格。
- 退出码只表示运行状态，与数据质量无关。

## 5. 大模型的位置

默认判定路径完全基于规则，评测期模型服务不可用时也能完整运行，模型服务消耗为 0。
`--use-llm` 时才要求 `LLM_*` 环境变量，缺失直接报错；此时只启用两个子代理（读说明文档、改写整改建议），
temperature 固定为 0，多次调用取一致结果，不一致落「待判定」，模型不下结论、不算分。详见 8.4 节。

## 6. 运行效率

- 按质量变体组多进程并行（`sqa.parallel`）：组间没有数据依赖，并行与串行结果逐字节一致（有测试覆盖）。进程数 = 容器可用 CPU 数（读取 CPU 亲和性与 cgroup 配额）与组数中较小者，可用 `--workers` 或环境变量 `SQA_WORKERS` 指定。公开集 30 个数据集：串行 33 分钟，6 进程约 12 分钟。

- 只依赖 PyYAML，镜像基于 slim，体积远低于 20 GB 上限。
- R01 先按文件大小分组，只对大小相同的文件计算 SHA-256，不全量读取 TB 级数据。
- 每个检查的耗时、资源峰值与 token 消耗写入 `08_运行日志/run.log.jsonl`，合计写入 `run_summary.json`。

## 7. 依据公开数据确定的设计

| 发现 | 设计 |
|---|---|
| 6 类数据、4 种标签结构 | 规格中声明 4 个标注族，按标签内容识别；检查按族适用 |
| 同类 5 个子集缺陷程度不同 | 全部受评数据集做全局排序（评分标准 v1.1 §2.5：不按组分别计分），另给出组内排序供说明差异来源 |
| 多个子集「有标签无数据」 | P01，critical |
| 部分标签成批缺字段 | S03（赛题必填字段）+ S04（同批对照，出现率 ≥ 75% 的字段） |
| `event_types` 汇总与事件明细不符 | S06 |
| 分割/矩形标注出现 `__OOV__` | C01（类别表） |
| ULF 事件时段超出文件时间窗 | B02 |
| HEK 事件无多边形（null/空数组） | 视为无几何，不判缺陷 |
| HEK 按时间窗匹配事件 | B02 对图像加匹配容差（默认 2 小时） |
| 个别字段量级异常（疑似单位换算） | N01 只落「待判定」，附偏离倍数，不直接判缺陷 |

## 8. 质量变体对照（v0.3.0）

需求说明：各数据集附有「由同一基础数据构造的不同质量版本」。公开数据中同一组变体的样本**同名一一对应**，
缺陷注入发生在个别版本的个别样本上（DMSP、EPB、ULF 已用全量数据确认）。

| 步骤 | 做法 |
|---|---|
| 分组 | 同一标注族、样本名集合 Jaccard ≥ 0.5 的数据集归为一组（`variants.min_jaccard`） |
| 参考 | 按独立检查的缺陷数排质量序，取质量序最靠前且该样本记录有效的版本为参考（v0.5.0 起；公开集实测发现缺陷在质量档间部分嵌套，多数投票会冤枉好版本） |
| 共有问题 | 同一样本在所有同源版本中都被同一检查判出：属基础数据特性，降级为待判定 |
| 元素匹配 | 先配完全相同的元素，再按「中心距离/目标尺度 + 时间偏移/时长 + 属性差异 + 类别差异」贪心配对，代价 > 2.0 视为不同目标 |
| 判定 | 未匹配的参考元素 → 漏标 X04；多出的元素 → 虚标 X05；类别不同 → 错标 X03；几何或时间不同 → 偏移 X06；数据指纹不同 → X02；样本整体缺失 → X01；其余字段不同 → X07 |
| 不确定 | 少于 3 个版本，或最干净版本孤立而另有内容获 3 个以上版本支持时，差异只进待复核队列，不判缺陷 |
| 去重 | 同一路径已被单数据集检查判出的，X03/X07 不再重复报告 |

没有同源版本的独立数据集，X 类检查判「不适用」并写明原因，单数据集检查照常进行。

## 8.1 单数据集物理一致性判据（v0.6.0）

为应对隐藏集逐个数据集运行、没有同源版本的情况，从公开集最干净版本中找出不变量，阈值依据实测分布并留余量：

| 检查 | 不变量 | 干净数据 | 阈值 |
|---|---|---|---|
| V04 | CME 动能 / (½·质量·速度²) | 0.95～1.05 | 偏离 > 15%（0.7.0 起属非计分轨 L2-B，只作待复核提示，见 8.3） |
| B03 | 活动区中心到日心距离 / 日面半径 | ≤ 1.01 | > 1.05 |
| B04 | 多边形像素面积 / event_npixels | 1.14～8.99 | < 1.0 或 > 10 |
| C04 | 事件类型与来源目录名（如 p2pi2 → Pi2） | 全部一致 | 不一致即判 |

标签中的 `fabricated`、`concept_swapped` 字段疑似注入工具遗留，不作判据。

## 8.2 评估过但未采用的图像内容判据

为提高单数据集模式下内容性缺陷的检出，用公开集做了两项可行性实验（以版本对照的结论为答案）：

| 实验 | 方法 | 结果 | 决定 |
|---|---|---|---|
| 框与图像内容是否吻合 | 框内像素相对日面背景的反差，比较偏移框与正常框 | AUC：HMI 0.44，AIA 0.62；1% 误报率下检出 ≤ 1% | 不采用：AIA 部分波段上活动区本身不突出，反差无区分度 |
| 图像本体是否被扰动 | 单张图像的高频能量、饱和比例、均值 | HMI 高频能量区分明显（1% 误报率下检出 68%）；AIA 无区分度（AUC 0.43） | 不采用：只对一类仪器有效、阈值依赖仪器；部分版本 68% 的图像被改动，无法在数据集内自适应 |

同时确认：被改动的图像没有发生几何变换（与原图翻转、旋转后的相关系数相同），框的偏移是单独注入的。

## 8.3 依据档位标签的修正（v0.7.0）

2026-10-19 收到评分标准 v1.1 附件一（30 个包的档位与污染项目）后，用 `tools/tier_eval.py` 逐包对照，修正如下：

| 现象（0.6.1） | 原因 | 修正 |
|---|---|---|
| CME P3 / P4 各报 1171 / 2928 处漏标 + 同数虚标（附件一：CME 全档无漏标虚标） | 大幅时间抖动超过匹配阈值，同一事件被拆成一漏一虚 | 同一样本内两侧未匹配元素按身份字段或数量一一配对，判为偏移 |
| AIA / HMI 的 P1 各报 10 / 18 处漏标虚标（附件一：P1 不含 L3，报出即误报） | 源数据中重复的事件身份字段不唯一，身份配对失效，整样本偏移后被拆成漏标 + 虚标 | 同上，身份字段相同即配对 |
| clean 包报出不通过（ULF 事件越界 122、数值异常 34、重复样本 11；HMI 重复标注 9 等） | 源数据固有问题，附件一说明不计入任何档位 | 参考版本同一位置同一判据也不通过的结论降级为待判定 |
| 数值扰动、CME 动能、物理量范围、时序数据改动报为不通过 | 附件一列为非计分轨（需外部基准），超阈值检出扣分 | 按缺陷代码弃报为待判定，写明需补充的基准材料 |
| AIA / HMI 图像像素改动报为数据改动 | 附件一无此污染项目 | 只列待复核 |
| EPB 的尺寸文本被改（L2-F）未检出 | D02 只取第一处尺寸声明 | 每一处尺寸声明都与 PNG 文件头比对 |
| HMI / AIA 虚构事件只能靠版本对照判出 | — | 新增 M03：事件身份标识与同批主流格式不符即疑似虚构（clean 版格式一致率 100%） |
| CME 类别错标判为结构不自洽 | CME 事件明细无类型字段 | 汇总类型与同批主流汇总不符时按类别错标（L2-P） |
| ULF 起止时刻抖动（L2-T）、参数失配（L2-M）混在文档一致性里 | — | D01 / D03 / X07 按字段细分缺陷代码 |

修正后：组内排序 30/30 与档位一致、预测档位 30/30、clean 包不通过 0 条、不在污染项目内的计分轨结论 3 条。

几何变化的细分阈值也来自档位标签：中心偏移 < 0.1 且 |ln 面积比| ≥ 0.15 的几何变化，在不含 L3-MIS 的 P1 中只有 0～2 处，
P4 中 512～629 处，据此判为覆盖不足 / 过度（L3-MIS）；EPB / DMSP 不含 L3-MIS，该细分只对外接框类标注启用。

## 8.4 模型子代理（v0.7.1，默认关闭）

模型只用在规则做不了、又不影响可复算的两处，`--use-llm` 时启用：

- **doc_claim_extractor（D04 的输入）**：需求说明书点名「说明文档声称覆盖的类别或时段在实际样本中缺失」。自由文本文档规则读不懂，
  交给模型抽取结构化声明；但模型不下结论——每条声明须附原文摘录且摘录必须逐字出现在文档中，同一文档抽取两次只采用一致的部分，
  比对由确定性程序完成。这样模型的随机性和幻觉都被挡在结论之外。
- **remediation_writer**：把整改建议改写得更具体（答辩 D-3「整改与补查建议的可执行性」），只写入评分卡说明字段。

没有交给模型的：核心缺陷判定（规则对照档位标签已 30/30，模型只会更贵更不稳定）、看图判框（像素判据实验区分度不足，见 8.2）。
效率分中模型消耗按名次计分且权重最高，所以默认关闭；是否在评测时开启，取决于隐藏集是否带说明文档、平台提供什么模型。

开发时另有两个工具用模型提效（不进入评测流程）：`tools/gen_profile.py` 生成新数据类型的标注族草稿并实测校验，
`tools/llm_review.py` 对照评分要求审阅交付文档。

## 9. 缺陷程度与质量分（评分准则 §2.4）

- **逐条程度**：偏移类缺陷带 `degree`，同一形态内两轴各归一到 [0,1]、1:1 加权。图像为「中心偏移/目标尺度」与「|ln 面积比|」；时间事件为「偏移秒/3600」与「偏移/时长」；时序数据带采样点增删数与改动行数。
- **数据集比例**：`quality.measures` 给出缺失、损坏与改动、错标、数值扰动、漏标、虚标、偏移、重复、结构与引用、文档、类别分布偏移、使用条件 12 项指标，每项写明分子、分母、来源检查，可直接复算；不可重推项全部弃报时该指标记「不可计算」，不按 0 计。
- **质量分**：`100 × (1 − Σ 权重·比例·严重度因子 / Σ 权重)`；不可计算的指标从分子分母同时移除并列入 `excluded_measures`，不按 0 分或满分计入。

## 10. 排序（评分准则 §2.5）

- **全局排序**：全部数据集按质量分降序；同分时依次比较关键缺陷单元数、最大单项比例、数据集标识，保证不输出并列。每一名都写出主要扣分因素和「领先下一名的原因」。
- **组内排序**：同一质量变体组内（无变体时为同一标注族）按同一规则排序。

- 已用发榜方档位标签标定（8.3 节）：组内排序与预测档位 30/30，clean 包零误报；各检查命中统计见 `calibration.tsv`，逐包对照见 `tier_eval.txt`。
